# FrameBoost 网页视频补帧

Edge / Chrome 扩展，用本机显卡运行 RIFE 神经网络，把网页视频实时补到 60、120 fps 或屏幕刷新率上限。显卡跟不上时退回 GPU 光流。画面全部在本机处理，不上传、不收集任何数据，没有运行时依赖，也不需要构建。

*A Chrome / Edge extension that interpolates web video to 60, 120 fps or the display's refresh rate with the RIFE network running on your own GPU through WebGPU. Everything stays on your computer.*

## 安装

- **商店版**：Chrome 网上应用店（上架后补充链接）。
- **开发版**：
  1. 下载或克隆本仓库。
  2. 打开 `chrome://extensions` 或 `edge://extensions`，打开“开发者模式”。
  3. 点“加载已解压的扩展程序”，选择仓库目录。
  4. 刷新已经打开的视频页面。

需要 Chrome / Edge 121 或更高版本。AI 模式需要支持 WebGPU 的独立显卡。想用在本地视频文件（`file://`）上，需要在扩展详情里打开“允许访问文件网址”。

## 使用

播放视频后自动生效，工具栏弹窗可以调整：

| 设置 | 说明 |
| --- | --- |
| 目标帧率 | 60 / 120 / 屏幕上限。输出取屏幕刷新率的整除帧率以保持匀速，例如 144 Hz 屏幕上，60 对应 72，120 对应 144 |
| 画质 | **AI**（默认）：RIFE 4.9，模型分辨率随显卡负载在 384p 到 1088p 之间自动调整，选好的档位会记住。精细 540p、均衡 360p、省电 270p 是光流引擎的运动估计分辨率。显示的都是原画质 |
| 实时帧率 | 在视频左上角显示 `24 → 144 fps` |

弹窗顶部的标签显示实际在用的引擎：“AI 补帧生效中”，或者“AI 未生效，正在用光流补帧”和原因。画质选项只代表你选了什么，显卡被游戏占满等情况下 AI 会自动退回光流，这时视频右上角也会提示一次，恢复时再提示一次。

快捷键 `Alt+Shift+F` 开关补帧，方便对比。宽度小于 400px 的视频（缩略图预览等）不处理。

## 工作原理

- `src/rife.js`：RIFE 4.9 的网络，直接写成 WGSL 计算着色器，不依赖任何 ML 运行时，权重在 `models/`。与 ONNX 模型的 CPU 结果逐帧对比差异约 118 dB。ONNX Runtime 的 WebGPU 后端在这个模型上有几何形变，所以没有用它。
- `src/neural.js`：AI 引擎。每对原始帧只推理一次，得到中间时刻的双向光流和混合遮罩，再用不动点迭代合成任意时刻，所以 24 → 120 的网络开销和 24 → 48 相同，每个输出帧只花一次轻量合成。端点处严格还原真实帧。GPU 队列是顺序执行的，一次完整推理会挡住后面所有画面，所以推理被切成小片，每次屏幕刷新先画一帧，等画面排进呈现队列后再执行一片。画布最大只到片源分辨率，1080p 视频全屏 4K 时也不会每帧多画四倍像素。
- `src/repair.js`：修复直条纹上的光流。网络由粗到细，条纹缩小后变成灰色，细层又会选中隔壁的条纹，黑白反相。这里对原图分块做 FFT 相位相关提出候选运动，只在周围分块全部呈周期性（次峰接近主峰）、对比度足够的区域，才在 RIFE 匹配失败或条纹非常规整时替换。规则这么保守是因为放宽后它会把车轮、脚踝这类遮挡复杂的区域撕碎。每对帧约 2 ms。
- `src/audio-delay.js`：AI 模式下画面固定晚 0.3 秒，给推理留出时间，声音经 WebAudio 延后同样的时长，所以音画保持同步。
- `src/engine.js`：WebGL2 光流引擎，AI 不可用时的后备。金字塔块匹配估计双向光流（含上一对帧的时域预测），经中值和联合双边滤波平滑，用往返一致性算置信度。合成时用不动点迭代把两帧分别变形到时刻 t，再按时间距离和置信度混合。往返一致性大面积失败时判定为切镜，直接显示最近的真实帧。
- `src/captions.js`：补帧时把原生 `<track>` 字幕重新画到画布上方，同时用 CSS 隐藏被盖住的原生字幕；画布一隐藏就交还给浏览器自己显示。
- `src/content.js`：找到页面上最大的播放中视频，在它后面插入一个不接收鼠标事件的画布，用 `requestVideoFrameCallback` 取帧和校准时钟。光流模式下暂停、跳转、缓冲时隐藏画布，直接露出真实视频；AI 模式下暂停时把延后的画面播完并停在最后一帧，声音也同时结束。
- `background.js`：只做两件事：响应快捷键；在用户点击后，为当前标签页的媒体请求添加 CORS 响应头。

AI 引擎需要 WebGPU，只在 HTTPS 页面和 localhost 可用；HTTP 页面自动用 WebGL2 光流。扩展不能调用 CUDA，WebGPU 用的是同一块显卡，但用不上 NVIDIA 光流硬件和 TensorRT。

## 已知限制

- **DRM 视频无法补帧**（Netflix、Disney+、Prime Video 以及多数付费平台）。浏览器不允许脚本读取这类画面，扩展检测到后会完全不介入。这是平台的版权保护，本扩展不尝试绕过。
- **光流模式下画面比声音晚约 50–60 ms**。补帧必须等到下一帧才能算中间帧，所以 24 fps 视频约晚一帧再加一次屏幕刷新。
- **AI 模式的操作延迟**：画面比视频实际进度晚 0.3 秒，声音同步延后，所以看电影没有音画差，但暂停、调音量会有 0.3 秒滞后。视频所在页面自己画的字幕（如 YouTube）跟着实际进度，比画面早 0.3 秒；原生 `<track>` 字幕会跟画面同步。
- **AI 模式达不到全分辨率模型**。RTX 5070 上 1080p 24 fps 的片源实时只能用 640p 模型，比光流软一些。
- **AI 模式需要显卡有余量**。显卡被游戏占满时 WebGPU 抢不到时间，扩展几秒内退回光流，弹窗会说明，每 60 秒重试一次。
- **页面自己把视频接入 WebAudio 时**声音无法延后，这类页面用光流。
- **帧率上不去屏幕刷新率**。60 Hz 屏幕最多就是 60 fps。
- **快速运动和遮挡边缘**仍会有变形或拖影。车轮辐条这类细而快、互相遮挡的场景仍有重影和弯曲。
- **低对比度的切镜可能漏判**，可能闪过一帧混合画面。
- **条纹每帧移动超过半个周期时方向判断不了**，条纹的运动方向可能和物体相反，就像视频里倒转的车轮。
- **原帧重复的视频**（比如 24 帧内容转成 30 fps 编码，或一拍二的动画）里重复帧不会被识别。
- **跨域直链视频**（`<video src>` 指向其他域名且没有 CORS）需要在弹窗点“重新加载视频”，会重新缓冲一次。依赖 Cookie 鉴权的地址可能仍然失败。
- **`<video>` 自身原生全屏时不补帧**，因为画布盖不到全屏元素上面；自定义播放器全屏的是外层容器，不受影响。
- **浏览器原生字幕**（`<track>`）由扩展重新绘制，样式固定为白字黑底；竖排字幕按横排显示。
- **带原生控制条的视频**鼠标移上去后约 2.5 秒内会让开，露出控制条。
- **HDR 视频**按 SDR 显示。用 WebAssembly 自行解码并画到画布上的播放器检测不到。

## 开发

需要 Node.js 22 或更高版本，以及本机安装的 Edge。

```bash
npm install
npm test
```

- `tests/quality.mjs`：光流引擎。渲染合成场景的 t=0 和 t=1，生成 t=0.5，与真实的 t=0.5 比较 PSNR，要求优于重复帧和交叉淡化，并检查硬切保持干净。
- `tests/neural.mjs`：AI 引擎。检查 t=0.5 和 t=0.25 优于交叉淡化、端点严格还原真实帧、靠近端点没有跳变、硬切干净。
- `tests/e2e.mjs`：在临时配置文件里加载扩展，播放真实的 H.264 视频，覆盖普通文件、MSE、跨域、DRM、原生字幕、全屏、暂停和跳转、GPU 上下文丢失、弹窗等场景。截图输出到 `tests/.output/`。

`node tests/webgpu-probe.mjs` 检查本机的 Edge 能否拿到 WebGPU 显卡（`chrome` 参数检查 Chrome）。

`npm run pack` 用 `git archive` 把已提交的扩展文件打成商店上传用的 zip。测试数据和模型对比见 [docs/benchmarks.md](docs/benchmarks.md)。
